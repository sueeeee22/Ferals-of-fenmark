# Ferals of Fenmark — Build Plan

Target: **Pokémon Red/Blue on the Game Boy**, at or above its quality, in a browser tab.
Not "inspired by". The comparison is meant to be made side by side, with screenshots.

---

## 0. The one architectural decision everything else hangs off

**The game is a pure reducer. The renderer is a pure function of game state. Nothing else.**

```
step(state: GameState, input: Input, rng: Rng) -> GameState     // src/core/*, zero DOM
draw(ctx, state)                                                 // src/render/*, zero logic
```

Consequences, all of them load-bearing:

- `gauntlet:playthrough` is not a browser puppet fighting flakiness. It is a Node script
  that feeds `Input` values into the *actual shipping reducer* and asserts it reaches the
  Champion. Real player inputs, no shortcuts, no test-only hooks, 1000× faster than Playwright.
- `gauntlet:sim` runs 10,000 battles by calling the same battle code the UI calls. There is no
  "simulation model" that can drift from the real game, because there is only one model.
- Save/load is `JSON.stringify(state)`. Determinism means a seed + input log reproduces a run
  exactly, which makes every bug reproducible from a save file.
- Rendering can be swapped, sped up, or skipped entirely without touching a rule.

The RNG is seeded xorshift128+, stored *in* the state, advanced explicitly. No `Math.random()`
anywhere in `src/core` — the type gauntlet greps for it and fails the build.

## 1. Directory contract

```
src/core/        pure logic, no DOM, no imports outside core.  ← the game
  rng.ts         seeded xorshift, serializable
  types.ts       the 12-type chart + effectiveness
  creature.ts    stats, damage formula, stat stages, status
  battle.ts      turn resolution state machine
  world.ts       tile grid, collision, warps, encounters, NPC LoS
  game.ts        top-level reducer: title → overworld → battle → menu
  save.ts        serialize / deserialize / migrate
src/data/        content. Mostly GENERATED by scripts/, never hand-typed at scale.
  species.gen.ts 150 creatures + legendaries, emitted by the statline generator
  moves.gen.ts   move table
  maps.gen.ts    compiled tilemaps
  dialogue/      hand-written. The exception to "generate, don't type".
src/render/      canvas 2D, 160×144 logical, integer scale
  forge.ts       procedural sprite generator (runs in Node AND browser)
  gb.ts          palette, tiles, text box, 8×8 font
src/ui/          scene renderers + input mapping. Thin.
scripts/         generators + the eight gauntlets
tests/           vitest unit tests
```

`src/core` importing anything from `src/render` or `src/ui` is a build failure.

## 2. Phases, in dependency order

Harness before feature, always. A gauntlet that has never failed has never been tested,
so each harness is written against a deliberately broken fixture first.

| # | Phase | Gate |
|---|-------|------|
| 0 | Tooling: eslint, tsx, npm scripts, all 8 gauntlets stubbed and *failing* | `gauntlet:types` |
| 1 | Type chart (12×12), stat/damage math, RNG | `gauntlet:types` |
| 2 | Battle engine — turns, crits, accuracy, status, stat stages, catching | `sim` |
| 3 | Statline generator → 150 species, evolution lines, learnsets | `schema` + `sim` |
| 4 | Sprite forge + `forge.html` contact sheet + critic loop | `visual` |
| 5 | Overworld: tiles, collision, warps, encounter tables, NPC line-of-sight | `playthrough` (partial) |
| 6 | Content: 8 gyms, badges, rival, Elite Four, items, boxes | `curve` |
| 7 | Dialogue, all of it, to TONE.md | `tone` |
| 8 | Audio (WebAudio chiptune), menus, polish | `visual` |
| 9 | Firebase layer — never a blocker, game is complete without it | `ship` |

Polish is continuous. There is no "polish phase" at the end; that is how projects ship
looking like prototypes.

## 3. Content generation strategy

150 statlines are **generated by a tuned script**, not written by a model. The generator takes
a compact species table (name, animal, family, types, stage, role archetype, evolution) and
derives base stats from stage budget + archetype weights + deterministic per-species jitter.
Balance is then a matter of tuning ~20 numbers and re-running, not editing 150 rows.

Learnsets likewise: each species draws from type-and-archetype move pools on a level schedule
that provably covers 1–60 with no gaps, because the scheduler is what guarantees it.

**Dialogue is the exception.** It gets written, by hand, to `TONE.md`, and rewritten when the
tone gauntlet says it is flat.

## 4. Fidelity targets (the actual Red/Blue bar)

- 160×144 logical resolution, 4-colour DMG palette, integer scaling only. No blur.
- 16×16 tile grid, 4-frame walk cycle, movement locked to tile boundaries.
- Text box: 2 lines, 18 chars wide, per-character typewriter, ▼ advance prompt.
- Damage formula shaped like Gen 1's (level term, atk/def ratio, /50, +2, modifier chain).
- Crit rate off base Speed, like Gen 1 — but *without* Gen 1's critical-hit bug.
- Level curve: gym-gated, monotonic, Champion around L55–62.
- 60fps on a mid-range phone: fixed 16.67ms step, dirty-rect canvas, zero per-frame allocation.

## 5. Where the fidelity deliberately exceeds Gen 1

Gen 1 shipped with bugs. Matching the bugs is cargo-culting, not quality.

- Special is split into Sp.Atk / Sp.Def. Gen 1's single Special stat is a known design flaw.
- Accuracy is not the 1/256-miss bug.
- Focus Energy actually works.
- Type chart has no dead types (Gen 1 Ice/Bug/Poison were dead weight; `gauntlet:sim` fails
  the build if any type's roster wins <35% or >65%).
- Status stacking rules are consistent rather than emergent from a memory bug.

## 6. Risk register

| Risk | Mitigation |
|------|-----------|
| Sprites read as noise, not animals | Phase 4 early, contact sheet + fresh-context critic loop |
| Balance never converges | Generator + 20 tuning knobs, not 150 hand edits |
| Playthrough bot soft-locks | Reducer purity + input log replay makes every lock reproducible |
| Dialogue lands flat / safe | TONE.md written before line one; hostile re-run of tone gauntlet |
| Budget dies mid-run | STATE.md rewritten every phase, for a reader with no memory |

## 7. Operating rules (mine, not the user's)

- Never send a critic anything the deterministic gauntlets have not already passed.
- Commit at every green gauntlet, tagged with the phase.
- Three failures of the same gauntlet by the same builder → `BLOCKERS.md`, move on.
- Sonnet for tables, harnesses, boilerplate, mechanical critique.
  Opus for the type chart, dialogue, and taste.
